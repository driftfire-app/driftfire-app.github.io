The outcome

Codex won.
Not because it was flawless.

It won because fewer correctness failures reached the developer, its verification exercised the real product, and its architecture made the drawing model, screen, network order, and app lifecycle independently testable.

“After this experience, Codex is clearly the winner, and it's going to become my primary model going forward.” The developer, after using both builds
The setup

A real feature, not a toy prompt

Driftfire normally generates its asteroid field. The assignment was to let players paint that field with a finger before a match: connected strokes become textured asteroids, erase removes rock, and two local players can draw simultaneously.

Input

The same opening brief

Both agents received the developer's complete request plus the same 12 KB engineering brief with named correctness traps.

Environment

Independent worktrees

Each agent implemented on its own branch and opened a pull request. Both used heavy review loops, but only Claude's branch crossed model families.

Measure

Burden on the developer

The useful question was not who emitted more code, but what survived into a working build without human correction.

Caveat: this is an evidence-backed case study, not a benchmark. Claude's primary ran Opus 4.8 at high effort; Codex's primary ran gpt-5.6-sol at medium. Setting Codex to high would nominally match the label, but not calibrate equal cross-vendor compute—and the supporting-agent budgets also differed. Environments, start times, reviewer influence, and later product conversations were not matched.

Three phases

Scope changed after the start

A flat score hides the most important methodological fact: the opening prompt was identical, but the later conversations were not. Persistence, basic Uplink support, live remote co-editing, and native iOS touch width must be read in sequence.

Core data model

Both strong

Both appended a safe style value, excluded it from Random, and correctly implemented connected shapes, texture cycling, extension, oldest-texture bridges, and same-texture erase splits.

Local multitouch

Codex

Claude's design named it but its first implementation deferred it; the developer had to repeat that it was required. Codex modeled simultaneous touches from the start.

First render

Codex

Claude first produced an off-black screen, then gray asteroids and the wrong background. Codex's first verified canvas used the real starfield and rock textures.

Verification

Codex

Claude's visual check missed a device-visible blank screen. Codex's framebuffer matrix found that a mapping test exercised an unused helper and replaced it with production-path coverage.

Persistence

Different products

Claude built a richer four-recent-plus-saved library. Codex built a simpler named library. Both needed reviewer hardening; Codex ultimately tested atomic and corrupt-data paths more deeply.

Uplink support

Different answers

Claude moved toward live co-editing. Codex initially used host authoring plus snapshot transfer. “Supports Uplink” was no longer one identical requirement.

Initial UI

Neither

Both first interfaces were poor. Claude's was rough and partly broken. Codex's library became polished only after the developer pointed it to the existing settings screen.

Remote co-edit

Codex

Both initially missed joiner rotation. Codex fixed presentation and inverse input, then proved it with a test and framebuffer. Claude remains unrotated, and simultaneous remote drawing crashes on device.

iOS brush width

Codex approach stronger

Claude's pressure-only path currently produces dots but not dragged lines on the observed iOS build. Codex added native contact width, fixed one Web compatibility regression, then iterated mainly on feel—not on rejecting the approach.

The recurring pattern

The developer repeatedly became the integration test.

Claude usually identified the right concerns in design. A human playing the build had to reveal where those concerns had not survived the trip through UI, engine geometry, network flow, and device input.

Render

The reported visual check passed while the actual device showed an off-black screen.

Presentation

Gray rock, no stars

The drawing preview discarded the game's textures and background until device feedback.

Requirement

Multitouch omitted

A requirement present in both the user request and Claude's own design needed a reminder.

Network flow

The separate network launch path skipped authoring and started the game on an empty board.

Co-edit

Rotation + crash

The joiner still sees the wrong orientation; simultaneous remote drawing crashes.

Device input

iOS drag regression

At the latest observed Claude build, taps make dots while dragged strokes do not draw lines.

Agent orchestration

Different delegation doctrine.

Neither primary model handed production code to another agent. Claude used subagents for parallel reconnaissance and cross-model review. Codex kept implementation centralized and saturated the branch with same-model review passes.

Claude · diversify

Flow: three Opus 4.8 explorers started in parallel → Opus implemented alone → fresh Sonnet 5 xhigh and gpt-5.6-sol medium reviewers checked six milestones.

Material catches: mismatched match geometry, rotated-toggle hit testing, and a saved-board deletion path.

Codex · repeat

1persistent spawned reviewer
26assignments to that reviewer
32fresh Codex CLI reviews

Flow: gpt-5.6-sol implemented alone → one continuing gpt-5.6-sol medium reviewer checked successive commits and fixes → fresh same-model CLI reviews supplied a second pass.

Boundary: zero exploration agents and zero implementation agents. The automatic low-effort approval guardian is infrastructure and is excluded.

Interpretation: Claude had greater role and model diversity. Codex had much higher review cadence. Codex's final quality reflects a strong primary implementation plus a relentless review/fix loop—not an unaided first pass. The attended-time estimate measures wall clock, not aggregate reviewer inference.

Test design

The strongest difference is semantic

Both suites are substantial and overlap on the core. Codex's unique assertions line up better with the bugs that make remote co-editing fail in production.

Claude uniquely covers

  • Fractional rim cells inherit the asteroid's texture.
  • A rotated local-two-player toggle is hit in transformed space.

Codex uniquely covers

  • Joiner board rotation and inverse touch mapping together.
  • Byte-identical host/joiner convergence with separate touch IDs.
  • Letterbox and pillarbox input mapping.
  • Snapshot-zero isolation of the joiner's local settings.
  • Transport loss during authoring.
  • Atomic persistence, backup, and corrupt-entry recovery.
The key weakness: Claude's remote co-draw test injects strokes after screen-to-board mapping and compares only the number of solid cells. Two different boards can have equal area, so that assertion cannot prove convergence or catch the unrotated joiner.

Bottom line

On this feature, Codex reduced the human burden.

Claude delivered strong design reasoning, richer persistence behavior, smooth terrain edges, and valuable tests. But too many requirements were understood in the abstract and lost at integration time. Codex produced the cleaner system, the stronger tests on the riskiest behavior, and the build the developer trusted more.
